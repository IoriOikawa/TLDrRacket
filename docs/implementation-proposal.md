# TLDrRacket 轻量完善方案（已确认）

日期：2026-10-22

用户已确认方案，并选择本次先交付 Linux VPS 部署文件；远程接入和上线不在本次执行范围内。

目标：保留 Python、HTML、CSS、原生 JavaScript，以及 Flask、Chroma、Gemini 的结构，让学生快速找到课程阅读材料中的相关位置，同时保持代码适合作为 RAG 学习示例。

## 已确认的问题

- `webserver.py` 使用固定 `k=5`，没有过滤分数。使用替身执行现有 API 函数时，即使所有检索距离都是 999，也会返回五个来源。
- 回答通过 retriever 获取上下文，随后 API 再检索一次以生成来源。两条路径没有共享同一份筛选结果。
- 前端在请求期间没有等待状态，也没有阻止连续提交；错误消息的调用位置还会被当成用户消息。
- 索引构建流程在 Notebook 中，缺少可复现的命令行入口、依赖清单和运行文档。当前检出目录没有 Chroma 索引或运行依赖，因此尚未进行真实模型调用。
- 代码固定使用旧模型，且依赖路径混用了新旧 LangChain 导入方式。

## 方案比较

1. **推荐：等待提示 + 单次检索和门槛过滤。** 维持现有 POST JSON 接口，用少量原生前端代码显示活动状态；服务端复用通过筛选的片段回答并返回来源。改动集中，部署容易解释。
2. **可选：SSE 阶段通知和逐字输出。** 能显示真实的检索、生成阶段并逐步呈现回答，但需要新增流式协议、分块解析、中断及部分失败处理。仅在明确需要此体验时采用。

## 第一版行为

### 1. 等待反馈

提交问题后立即显示等待动画、“正在查找材料并组织回答”及已等待时间；请求期间禁止重复提交。成功、失败、超时后都恢复输入状态。支持键盘操作、读屏状态通知和减少动画偏好。

保留当前配色、主题切换和页面布局。等待状态不显示虚构的进度百分比或未经服务端确认的阶段。

### 2. 检索与查找点

统一执行一次向量检索，再过滤、按文件和页码去重，最后保留最多五个查找点。回答只使用这些查找点对应的片段，前端展示同一份来源。

新索引显式固定距离度量，配置最大允许距离；距离越小越相近。初始阈值用课程内问题、无关问题和边界问题校准，并记录校准方法。阈值是检索启发式，不能保证语义相关性绝对正确；不把距离或相似度宣传为答案置信度。

通过门槛的查找点不足五个时只展示实际数量。没有结果时返回明确的“没有找到足够相关的材料”和空来源数组，不调用生成模型。存在相关片段但仍不足以回答时，提示模型明确说明材料不足。

查找点展示文件名、从 1 开始的 PDF 页码和片段摘要，并可打开 PDF 对应页。内部保留片段 ID。只允许访问配置的数据目录内的文档，不能通过来源路径读取任意本地文件。

### 3. 可复现运行与文档

保留 `webserver.py` 为 HTTP 入口，把配置与共享检索逻辑放入一个小型 Python 模块，另加一个 Python 索引构建脚本。Notebook 保留为学习与实验材料；README 指明正式运行入口。

索引脚本沿用现有 800 字符切块、80 字符重叠的起点，保留文件、页码和片段 ID。提供明确的首次构建、重复运行和重建流程；记录嵌入模型与距离配置，避免更换模型后误用旧索引。构建索引是独立操作，不在每次启动服务器时重新生成嵌入。

README 覆盖项目用途、数据流、安装、配置、索引构建、启动、接口、分数与阈值、更新材料、常见故障、自托管，以及最小 RAG 的局限。补充依赖清单和不含真实密钥的环境变量示例。

当前模型需迁移为可配置、仍可用的 Gemini 生成与嵌入模型。嵌入模型变化必须重建索引，并重新校准门槛。最终默认值在实现时结合官方文档及 SDK 支持验证。

### 4. 自托管

生产入口使用 Gunicorn，继续由 Flask 提供页面与 API。为索引设置持久目录、健康检查、请求长度限制和超时；错误以用户可理解的信息返回，详细诊断留在服务端。

用户已确认部署到自己的 Linux VPS／服务器。采用 Python 虚拟环境安装依赖，Gunicorn 监听本地端口，systemd 管理进程与重启，Nginx 反向代理并接入域名和 HTTPS。补充 Gunicorn 的 Python 配置、systemd 服务示例和 Nginx 配置示例；这些是运行配置，不引入新的应用编程语言。

应用使用独立服务用户运行，API 密钥通过服务器环境文件注入。Chroma 索引放在可写的持久目录，代码升级和服务重启保留该目录；索引重建由明确的独立命令执行。首次构建、升级、回滚、日志查看及索引备份步骤写入部署文档。

本次按用户要求交付可审查的配置和步骤，不连接服务器。将来实际上线仍需要服务器系统、域名、部署入口及适当的访问权限；上线后再执行目标平台验收。

## 验证标准

- 使用 Python 标准库测试工具及替身，验证 0、1、5 个通过门槛的结果、边界距离、重复页去重、空索引、无结果时不调用模型、回答与来源共享同一批片段。
- 验证非法请求、模型异常、请求超时和安全文档路径处理。
- 浏览器确认等待状态立即出现、请求期间不能重复提交、完成或失败后可再次提问，来源能定位 PDF 页码。
- 在真实索引和有效 API 配置下试运行课程内与课程外问题，记录门槛表现及剩余误检。没有有效密钥时明确区分替身测试和真实端到端验证。
